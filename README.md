# 文章読み上げ

ブラウザ標準の Web Speech API（`SpeechSynthesis`）を使用して、日本語の文章を読み上げるシンプルな静的Webアプリです。画像から文字を読み取る通常のOCRは、ブラウザの中だけで動作し、APIキーもサーバーも必要ありません。さらに、選んだときだけAIを使う「AIで高精度OCR」「AIで翻訳・要約」「AI音声で読み上げ」も利用できます。AIの処理は Cloudflare Workers の AI Binding と Cloudflare AI Gateway（Auto Router・Unified Billing）で行うため、AIサービスごとのAPIキーは要りません。

## 使い方

1. `index.html` を Chrome、Edge、Safari などの対応ブラウザで開きます。
2. 大きな入力欄へ読み上げたい文章を入力、または貼り付けます。
3. 必要に応じて「音声」と「読み上げ速度」を選びます。クリップボードのボタンの下にある**「✨ AI音声で読み上げ（有料）」をONにすると**、ブラウザの音声のかわりにAI音声で読み上げます。
4. 「読み上げ」を押すと再生が始まります。
5. 再生中は「一時停止」「再開」「停止」を利用できます。

「読み上げ」をもう一度押すと、現在の再生を停止し、入力欄にある文章を先頭から読み上げます。長い文章は文末や改行を目安に分割し、順番に再生します。

「入力テキスト」の見出しにある「コピー」を押すと、入力欄の文章をすべてクリップボードへコピーします。コピーできると、ボタンの表示と画面上の案内が「○文字をコピーしました。」に変わり、しばらくすると元へ戻ります。読み取った文章をほかのアプリへ渡して要約したいときなどに使えます。

「現在読み上げ中」には入力文章の改行が反映され、ブラウザから読み上げ位置を取得できる場合は、現在読んでいる語句が黄色でハイライトされます。

ブラウザ側の不具合で読み上げが無言のまま止まったり、特定の箇所で合成に失敗したりした場合は、自動的に検知して直前の位置から読み直します。同じ場所で繰り返し止まるときは、その箇所を数文字だけ飛ばして続きを読み上げ、それでも進めない場合は次の文へ進みます。一度も読み上げられないまま失敗が続く場合だけ、音声を変更するようご案内します。

長い文章は読み上げの単位（ページ）ごとに区切られ、ポップアップの下に進み具合がドットで表示されます。ドットの左右にある「◀」「▶」を押すと、ページ単位で読み飛ばしたり聞き直したりできます。キーボードの `←` `→` キーでも同じ操作ができます（入力欄や速度の調整を操作しているあいだは、キーでのページ送りは行いません）。一時停止中にページ送りしたときは、そのまま一時停止を保ち、再開するとその位置から読み上げます。ページ送りはブラウザの音声のときだけ使えます（AI音声は1ページずつ音声を作って再生するため対象外です）。

読み上げを押しても音が出始めないことがあるため、音が出るまでは案内表示が「音声の準備をしています…」になります。ほかのアプリが音声を使っているなどの理由で始まらないまま1.6秒（オンライン音声は5秒）を過ぎた場合は、音声エンジンを解除して自動的に読み上げ直します。あわせて、画面を最初に触った時点で音声エンジンを起こしておき、初回の開始の遅れを減らしています。

「クリップボードの文章・画像を読み上げ」を押すと、以前の文章と読み上げをクリアしてから、コピーしてある文章を入力欄へ取り込み、すぐに読み上げます。画像をコピーしている場合は、その画像から文字を読み取ってから続けて読み上げます。貼り付けた文章に含まれる絵文字と、何も書かれていない空行（空白やタブだけの行を含む）は自動的に削除されます。Obsidianからコピーした文章の「関連ノート: Knowledge/…、Knowledge/…」のように参照先のノートのファイル名だけを並べた行も削除し、文中の `[[ノート名|表示名]]` は表示名だけを読み上げます。Gemini・ChatGPTなどのチャット画面からコピーした文章に含まれる**プログラムのコードとその実行結果**（```で囲まれた部分や、画面上でコードとして表示されていた部分）も、直前の「Python」「コードの出力」のような見出しや「コードを表示」の行とあわせて削除し、読み上げません。ただし、メールの下書きのように「Plaintext」「Text」「Markdown」と表示された文章のかたまり（```plaintext など）は、見出しだけを削除して中身を読み上げます。コピーの仕方によって「Plaintext」の見出しが入らない場合もあるため、見出しがなくても、中身が日本語の文章でプログラムらしい行が少ないかたまりは、文章とみなして読み上げます。ブラウザからクリップボードの読み取り許可を求められる場合があります。

許可確認を表示せずに利用するには、入力欄を選択して `Ctrl + V`（スマートフォンでは長押しして「貼り付け」）を実行してください。以前の文章が自動的にクリアされ、絵文字と空行を削除した文章だけをすぐに読み上げます。

PDFやWebページからコピーした文章は、画面の表示幅で改行されていることがあります。そのままでは「〜便利な仕」「組みでも〜」のように語の途中で読み上げが切れるため、**貼り付けた時点で折り返しの改行をつなぎ直します**。句点で終わる行の改行、箇条書き・一覧の行頭、段落のあいだの空行、表示幅に届かない見出しのような行の改行は、区切りとしてそのまま残します。

## 読み方を指定している言葉

名字などで、音声が違う読み方をしてしまう言葉は、**読み上げるときだけ**決まった読み方に置き換えます。入力欄や「現在読み上げ中」の表示は元の文字のままで、ハイライトの位置もずれません。ブラウザの音声とAI音声のどちらにも効きます。

| 言葉 | 読み方 | 置き換えないとき |
| --- | --- | --- |
| 平野 | ひらの（名字） | 「関東平野」「大平野」のように前に漢字が続くとき、「平野部」「平野地帯」のように地形の意味で使われるとき（「へいや」と読みます）。ただし「営業部平野さん」のように後ろに「さん」「様」「部長」などが続くときは、名字として「ひらの」と読みます |
| 山本清乃 | やまもと（下の名前は読みません。「山本清乃さん」は「やまもとさん」） | なし |
| 伊勢着 | いせちゃく | なし |
| 楳生 | うめぶ（名字。「楳生 仁子さん」は「うめぶさん」） | なし |
| 谷内 | やち（名字。「谷内 好和さん」は「やちさん」） | 前に漢字が続くとき（地名など） |

言葉を追加したいときは、`script.js` の `READING_OVERRIDES` に追記します。

## 処理方法を選ぶ

入力欄の下の「処理方法」で、画像の読み取り方と、読み上げる前のAI処理をまとめて選べます。選んだ内容はブラウザに保存され、次に開いたときもそのまま使われます。

画面の**一番上**にも、同じ内容を切り替えられる横一列の簡易選択（🔊 無料OCR / 🔍 高精度 / 📝 要約 / 📑 詳細要約 / 🌐 翻訳）を置いています。上下どちらを操作しても同じ設定になるので、スクロールせずに切り替えられます。

> 変更したのに画面が変わらないときは、ブラウザが以前のページを覚えている場合があります。ページを再読み込み（スマートフォンでは下へ引っ張る、パソコンでは Ctrl+Shift+R / ⌘+Shift+R）してください。`public/_headers` で `index.html`・`style.css`・`script.js` は毎回新しいかどうかを確かめる設定にしています。

| 処理方法 | 画像を入れたとき | 文章を入れたとき | AIの利用 |
| --- | --- | --- | --- |
| 🔊 無料OCRで読み上げ（初期値） | 無料OCR → 読み上げ | そのまま読み上げ | なし |
| 🔍 高精度OCRで読み上げ | AI OCR → 読み上げ | そのまま読み上げ（AIは呼びません） | あり |
| 📝 要約して読み上げ | AIで読み取り＋要約（1回）→ 読み上げ | 要約 → 読み上げ | あり |
| 📑 詳細要約して読み上げ | AIで読み取り＋詳細要約（1回）→ 読み上げ | 詳細要約 → 読み上げ | あり |
| 🌐 翻訳して読み上げ | 無料OCR → 翻訳 → 読み上げ | 翻訳 → 読み上げ | あり |

- 「翻訳して読み上げ」を選んだときだけ、翻訳先の言語（日本語・英語・中国語・韓国語）を選べます。初期値は日本語です。
- 要約・詳細要約は、入力が何語でも**日本語**で返します。入力された文章の言語は、AI側で自動的に判断します。
- **PWBS**（Project Work Breakdown Structure の略。おおむね機種の意味で使われます）は、自分の担当かどうかを判断する情報のため、要約でも省略しません。PWBSの名前・番号は番号やコードでも残し、複数あるときはそれぞれを挙げて、どのPWBSにどの内容が当てはまるかが分かるようにまとめます。
- 人の名前は、**所属部門が分かるときは部門を付けて**名字で呼びます。例えば、ドキュメントDBのメールで登録部門が「ＳＥ」、登録者が「木村 幸代」なら「SE部門の木村さん」と要約します。所属が分からないときは「木村さん」のように名字だけで呼びます。
- 社外の人（村田機械・ムラテック・Muratec 以外の会社の人）は、**会社名を省略せず**「KOKUSAI ELECTRICの青山さん」のように会社名を付けて名字で呼びます。会社名は署名・名乗り・メールアドレスのドメインなどから分かる範囲で付けます。
- **画像を要約・詳細要約するときは、無料OCRを使わず、画像をそのままAIへ渡します。** 無料OCRで崩れた文字を要約すると、読み取りの誤りがそのまま要約の誤りになるためです。読み取り（書き起こし）と要約は**1回の呼び出し**でまとめて行うので、AIへ送る回数は以前と同じ1回です。画像の分だけ入力の料金は少し増えますが、ブラウザ内の無料OCR（言語データの読み込みと認識）を待たなくてよくなるため、全体の時間はほぼ変わらないか短くなります。読み取った文章は入力欄へ、要約は「AIの結果」欄へ入ります。要約だけを受け取れなかったときは、読み取った文章をあらためて要約します。
- 詳細要約は、通常の要約より丁寧にまとめます。要点だけでなく理由・背景・具体例・数値なども残し、長さは元の文章のおよそ3〜5割が目安です。
- AIを使う4つ（高精度OCR・要約・詳細要約・翻訳）は、同じパスワード認証が必要です。認証済みであれば、そのまま使えます。
- **AIの結果は、入力欄とは別の「AIの結果」欄に入ります。** 元の文章は入力欄にそのまま残るので、失われることはありません。翻訳・要約されたかどうかも一目で分かります。
- 「AIの結果」欄があるときは、**そちらの文章を読み上げます**。手で直してから読み上げることもできます。「✕ 消す」を押すと、元の文章を読み上げる状態へ戻ります。
- 同じ文章・同じ設定で続けて読み上げても、AIへ送るのは1回だけです。文章や翻訳先の言語を変えると、あらためて処理します。
- 読み上げ中は、「現在読み上げ中」の**すぐ右に、実際に行ったこと**が2つの印で出ます。選んだ処理方法ではなく、実際の動きを示します。

  | 印 | 意味 |
  | --- | --- |
  | 📄 文字 | 入力欄へ文字として入れた文章 |
  | 📷 画像 | 画像から読み取った文章 |
  | AIなし（灰色） | AIを使っていない＝**料金はかかっていない** |
  | ✨ AIで読取／✨ AIで要約／✨ AIで翻訳（紫） | AIを使った＝**料金がかかっている** |

  例えば「🔍 高精度OCRで読み上げ」を選んでいても、**文字を入力したときはAIを使いません**（高精度OCRは画像のときだけ働きます）。そのときは「📄 文字」「AIなし」と出るので、AIへ送ったかどうかが一目で分かります。印にマウスを重ねると、詳しい説明が出ます。
- 読み上げ中に**音声の選択やAI音声の切り替え**を変えても、その読み上げには反映されません。次の読み上げから変わります。
- **処理方法を切り替えても、読み上げは始まりません。**上下どちらの切り替えも設定が変わるだけなので、切り替えたあとに「読み上げ」のボタンを押してください。読み上げ中に変えても、その読み上げには反映されません。表示される処理方法も、読み上げを始めたときのままです。「停止」してから「読み上げ」を押し直してください。

### 翻訳・要約されなかったとき

AIが原文をそのまま返すことがあります（すでにその言語で書かれている、読み取った文字が崩れている、など）。そのときは、サーバー側で**もう一度だけAIへ問い直します**。それでも変わらなかった場合は、「AIの結果」欄の見出しが **「◯◯に翻訳（変わりませんでした）」** に変わり、色が付きます。処理されたのかどうかを、見て判断できるようにするためです。

変わらなかったときは、次をお試しください。

- 画像から読み取った文章が崩れているときは、「🔍 高精度OCRで読み上げ」で読み取ってから、翻訳・要約を選び直す
- 翻訳先の言語が、元の文章と同じ言語になっていないか確認する

## AI音声で読み上げる（有料）

ブラウザの音声のかわりに、**AIの音声モデルが作った音声**で読み上げられます。料金がかかるため、**チェックをONにしたときだけ**使います。OFFのあいだは、これまでどおり無料のブラウザの音声で読み上げます。

### 使い方

「クリップボードの文章・画像を読み上げ」のすぐ下にある **「✨ AI音声で読み上げ（有料）」のチェックを入れる**と、AI音声で読み上げます。OFFのあいだは、これまでどおり無料のブラウザの音声です。

「音声」の選択は、2つに分かれています。

| 選択 | 料金 | 内容 |
| --- | --- | --- |
| 音声（ブラウザ・無料） | 無料 | 端末に入っている音声です（「Microsoft 七海」を優先します） |
| ✨ AI音声（有料） | AI Gateway の利用料金 | チェックを入れたときに使う声です。8種類から選べます |

**ページを開き直すと、チェックはOFFに戻ります**（つけたまま使い続けて、気づかないうちに料金がかかることを防ぐためです）。

いま何をしているか（「待機中」「AI音声を作っています…（1 / 3）」「読み上げ中です」など）は、**この切り替えのすぐ下**に出ます。

選べる声は **Aoede（軽やかな声・初期値）**／Kore（落ち着いた声）／Puck（明るい声）／Charon（説明に向いた声）／Leda（若々しい声）／Achird（親しみやすい声）／Vindemiatrix（やさしい声）／Sulafat（あたたかい声）です。増やすときは、`public/script.js` の `AI_VOICES` と `worker/ai/speech.js` の `ALLOWED_VOICES` の両方へ追加してください。

**読み上げ速度**は、ブラウザの音声とAI音声で別々に覚えます。初期値はブラウザの音声が2.0倍、**AI音声は1.0倍**です。

### 動き

1. 文章を120文字ずつに区切り、音声モデル（既定は `google/gemini-3.8-flash-lite-tts`。Cloudflare AI Gateway の Unified Billing 経由で使うため、GoogleのAPIキーは要りません）へ順番に音声を作ってもらいます。Auto Router（`cloudflare/auto`）は音声の生成に対応していないため、AI音声だけは日本語に対応した音声モデルを指定しています（`wrangler.jsonc` の `AI_TTS_MODEL` で変更できます）。
2. **最初のひとかたまりができた時点で再生を始め、次の音声は再生中に作ります。**待ち時間を短くするためです。
3. 「一時停止」「停止」「読み上げ速度」は、ブラウザの音声と同じように使えます。速度は**再生中でもすぐに変わります**。
4. **AI音声では、終了アナウンス（「〜を終了します。」）は読み上げません。**
5. **同じ文章・同じ声をもう一度読み上げるときは、作り直しません**（料金がかからないようにするためです）。覚えておく音声の量には上限があり、古いものから忘れます。
6. AI Gateway が混み合っている（`TTS-BUSY`）ときは、**少し待ってから自動でやり直します**（最大2回）。利用上限に達した（`TTS-LIMIT`）ときは、待っても作れないためやり直しません。

「翻訳」「要約」「高精度OCR」と組み合わせることもできます。そのときは「現在読み上げ中」の印が「✨ AIで翻訳＋音声」のようになり、AIをどこに使ったかが分かります。

### 音声を保存する

「✨ AI音声で読み上げ」の右に「⬇ 保存」ボタンが常に表示されます。AI音声で最後の区切りまで音声を作り終えると押せるようになり、「⬇ 保存 ◯秒」と表示されます。押すと、読み上げた音声を**1つのWAVファイル**（16ビット・モノラル）としてダウンロードできます。

- ファイル名は `yomiage-<声の名前>-<日付>-<時刻>.wav` です。
- 途中までの音声は短いファイルになるため、**最後まで作り終えるまでは保存ボタンを押せません**（灰色の点線で表示）。途中で停止した場合も保存できません。
- 新しく読み上げ始めるか、クリップボードから読み込み直すと、保存ボタンは押せない状態に戻ります。

1回に渡せる文章は300文字まで（`worker/routes/tts.js` の `MAX_TEXT_LENGTH`）で、画面側は120文字ずつ（`AI_TTS_CHUNK_LENGTH`）に区切って送ります。AI音声で出る印は、下の「うまくいかないときの調べ方」を参照してください。

## 画像から文字を読み取る（OCR）

画像をコピーした状態で「クリップボードの文章・画像を読み上げ」を押すと、その画像に写っている文字を読み取り、続けてそのまま読み上げます。スクリーンショットを撮ってボタンを押すだけで、画面に写っている文章を聞けます。

コピーした画像を入力欄へ `Ctrl + V` で貼り付けた場合は、文字を読み取って入力欄へ入れるところまでを行います。読み上げは自動では始まらないので、内容を直してから「読み上げ」を押してください。

どちらの場合も、文章と画像の両方がコピーされているときは、これまでどおり文章を読み上げます。

画像の読み取りには「無料OCR（Tesseract.js）」と「🔍 高精度OCR（AI）」の2つがあり、入力欄の下の「処理方法」で選びます。処理中は、選んだ方法に合わせた表示が出ます（無料OCRは進捗率、高精度OCRは「AIで文字を読み取っています…」）。

- 文字認識には [Tesseract.js](https://github.com/naptha/tesseract.js) を使用し、日本語（`jpn`）で読み取ります。APIキーやサーバーは不要です。
- Tesseract.js本体と日本語の学習データはCDN（jsDelivr）から取得するため、初回の読み取りだけインターネット接続が必要で、少し時間がかかります（学習データは十数MB）。2回目以降はブラウザのキャッシュが使われます。
- 読み取った文章では、日本語の文字と文字の間に入った不要な空白と空行を自動的に削除します。
- 画面の折り返し位置に入った改行は、貼り付けた文章と同じように、続きの文としてつなぎ直します。「〜リアルタイムで測」「定値を表示する〜」のように語の途中で改行されていても、途切れずに読み上げます。OCRは1つの文の途中にも空行を入れるため、読み取った文章では空行をまたいでも前後をつなぎます（貼り付けた文章では、空行は段落の区切りとしてそのまま残します）。
- 画面のスクリーンショットのように、文字がはっきり写った画像ほど正しく読み取れます。写真の傾き、手書き文字、背景の模様、小さすぎる文字は読み間違えることがあります。

## AIで高精度OCR

通常のOCR（Tesseract.js）でうまく読み取れない画像のために、Cloudflare AI Gateway 経由でAIに画像を読ませる「🔍 高精度OCR」を用意しています。レイアウトが複雑なスクリーンショットや、通常OCRが文字を取りこぼす画像に向いています。

1. 入力欄の下の「処理方法」で「**🔍 高精度OCRで読み上げ**」を選びます。初めて使うときは、パスワードの入力を求められます（下の「パスワード認証」を参照）。
2. これまでどおり画像をコピーして貼り付ける、または「クリップボードの文章・画像を読み上げ」を押します。**この1回の操作で**、AIによる読み取りまで進みます。
3. 読み取った文章が「入力テキスト」へ入ります。

- AIを呼び出すのは、**高精度OCR・要約・詳細要約を選んでいるときに画像を読み取ったときだけ**です。ページを開いたとき、処理方法を切り替えたとき、文章だけを読み上げるとき、無料OCRのときには呼び出しません。
- 画像を読めるモデルは、Auto Router（`cloudflare/auto`）が画像に対応したモデルの中から自動で選びます。
- **AI OCR・要約・詳細要約を選んでいるときだけ、画像がAIへ送信されます。** 通常OCRはブラウザの中だけで完結し、画像は外部へ送信されません。画像はサーバーに保存しません。
- 大きすぎる画像は、文字が読める品質を保ったままブラウザ側で縮小してから送信します（長辺2000px・JPEG）。

### 通常OCRとの使い分け

| | 無料OCR（Tesseract.js） | 高精度OCR（AI） |
| --- | --- | --- |
| 料金 | 無料 | AI Gateway の利用料金 |
| 処理する場所 | ブラウザの中だけ | Cloudflare Workers → AI Gateway → AIの提供元 |
| 画像の送信 | なし | あり（選んだときだけ） |
| 向いている画像 | 文字がはっきりした簡単な画像 | 複雑なスクリーンショット、通常OCRで読み取れない画像 |

## AI処理の仕組み（Cloudflare Workers AI・AI Gateway）

AIの処理は、**Cloudflare Workers の AI Binding → Cloudflare AI Gateway** を通して行います。AIサービスごとのAPIキー（以前の `GEMINI_API_KEY` など）は使いません。

```text
ブラウザ ──(/api/ocr・/api/ai・/api/tts)──▶ Cloudflare Worker（worker/）
                                              │ env.AI.run(モデル名, 入力, { gateway: { id: "yomiage" } })
                                              ▼
                                   Cloudflare AI Gateway
                                   ・Auto Router（cloudflare/auto）がモデルを選ぶ
                                   ・Unified Billing（Cloudflareのクレジットで支払い）
                                   ・Spend Limits（利用上限）・ログ・分析
                                              ▼
                              AIの提供元（Workers AI・Google・Anthropic・OpenAI など）
```

| 機能 | 処理方式 | 既定のモデル（設定名） |
| --- | --- | --- |
| 無料OCR | これまでどおりブラウザ内の Tesseract.js | なし（AIを使いません） |
| 高精度OCR | Auto Router（画像に対応したモデルから自動選択） | `cloudflare/auto`（`AI_TEXT_MODEL_AUTO`） |
| 要約・詳細要約 | Auto Router | `cloudflare/auto`（`AI_TEXT_MODEL_AUTO`） |
| 翻訳 | Auto Router | `cloudflare/auto`（`AI_TEXT_MODEL_AUTO`） |
| 通常読み上げ | これまでどおりブラウザの音声 | なし（AIを使いません） |
| AI音声 | 日本語に対応した音声モデル（Unified Billing） | `google/gemini-3.8-flash-lite-tts`（`AI_TTS_MODEL`） |
| 音声ファイル保存 | これまでどおりブラウザでWAVを組み立てて保存 | — |

AIの処理（`worker/ai/`）は、画面や認証と切り離した関数（`recognizeImage`・`summarizeText`・`translateText`・`synthesizeSpeech` など）にしてあります。ほかの自作アプリ（MyBooks など）でも、`worker/ai/` をそのまま使えます（必要なのは AI Binding と `AI_GATEWAY_ID` だけです）。

### AIモデルの選び方（自動選択／固定モデル）

設定欄の上の「AIモデルの選び方」で選べます（初期値は「自動選択」。選んだ内容はブラウザに保存されます）。

| 選択 | 文章・画像の処理で使うモデル | 説明 |
| --- | --- | --- |
| 自動選択（おすすめ） | `cloudflare/auto`（`AI_TEXT_MODEL_AUTO`） | 処理の内容・難しさ・料金・期待される品質に合わせて、Cloudflare の Auto Router がモデルを選びます |
| 固定モデル | `google/gemini-3.8-flash`（`AI_TEXT_MODEL_FIXED`） | 管理者が決めたモデルを毎回使います |

- アプリの中では、モデルの選び方を細かく判定しません。選び方は Cloudflare 側（Auto Router・Model Aliases・Dynamic Routes）に任せます。
- `AI_TEXT_MODEL_AUTO` には `custom/〇〇`（Model Alias。Smart routing で自分が選んだモデルの中から自動選択）や `dynamic/〇〇`（Dynamic Route）も指定できます。モデルを変えるときも、アプリのコードは書き換えず、`wrangler.jsonc` の `vars` かダッシュボードの変数を変えるだけです。
- Auto Router が選べるモデルを絞りたいとき（高額なモデルを使わせたくないときなど）は、`AI_AUTO_ALLOWED_MODELS`（例: `anthropic/claude-haiku-5.5,google/gemini-3.8-flash`）または `AI_AUTO_ALLOWED_PROVIDERS`（例: `workers-ai,google-vertex-ai`）を設定します。AI Gateway へ `cf-aig-allowed-models` / `cf-aig-allowed-providers` として渡します。
- 画面の一番下の「使用AIモデル」の表には、選び方と、指定しているモデル名（`/api/models` から取得）が出ます。

### 実際に使ったモデルの表示

読み上げのたびに、状態表示のすぐ下へ**実際に使ったモデル**を表示します（例：「anthropic/claude-haiku-5.5（自動選択） ・ google/gemini-3.8-flash-lite-tts」）。

- 実際のモデル名は、AI Gateway の応答ヘッダー `cf-aig-routed-model` から取得します（AI Binding を `returnRawResponse` で呼び、ヘッダーを読み取ります）。
- 取得できないときは、**推測したモデル名は出さず「自動選択」と表示します。**
- 処理中・完了・エラーなどの状態は、これまでどおり状態表示（「AIで要約しています…」「読み上げが完了しました」など）に出ます。

## 料金の管理

- **Unified Billing**：外部の提供元（Google・Anthropic・OpenAI など）のモデルの料金は、Cloudflare のクレジットから支払われます。提供元ごとのAPIキーや請求は要りません。クレジットの購入時に5%の手数料がかかり、推論の料金は提供元と同じです。
- **Spend Limits（利用上限）**：AI Gateway の設定で、月ごとなどの上限額を決められます。上限はダッシュボードでいつでも変えられ、アプリの変更は要りません。上限に達すると、画面に「〜の利用上限に達したため、いまは利用できません。…（AI-LIMIT）」と表示します。機能ごとの上限にしたいときは、リクエストに付けている `feature`（`ocr`・`summarize`・`translate`・`tts` など）のメタデータで分けられます。
- **Workers AI の無料枠**：Workers AI（`@cf/...` のモデル）は、1日あたり10,000 Neurons まで無料です。Auto Router が Workers AI のモデルを選んだときに無料枠を使えるよう、ゲートウェイの「Workers AI billing」は既定（Workers の料金）のままにしておくことをおすすめします（Unified billing に切り替えると、Workers AI の分もクレジットから支払われます）。
- **ダッシュボードで確認**：利用料金・リクエスト数・使用モデルは、ダッシュボードの **AI → AI Gateway → yomiage → 分析（Analytics）/ ログ（Logs）** で確認できます。
- **不要な呼び出しを減らす仕組み**：同じ文章・同じ設定で続けて読み上げても、AIへ送るのは1回だけです。AI音声も、同じ文章・同じ声は作り直しません。画像の要約は、読み取りと要約を1回の呼び出しで行います。サーバー側でも、同じ利用者からのAIの呼び出しを10分あたり300回までに制限しています（`AI-429` / `TTS-429`）。
- **やり直しの上限**：自動でのやり直しは回数を決めて行い、無制限には繰り返しません（固定モデル・AI音声は AI Gateway 側で最大2回、空の返事・原文のままの返事は1回だけ、AI音声の混雑は画面側で最大2回）。
- 有料サービスの契約・クレジットの購入・自動チャージ（auto top-up）は、アプリからは行いません。必要に応じて管理者がダッシュボードで行います。

## セキュリティ

- **ログ**：入力した文章や画像には機密情報が含まれることがあるため、AI Gateway のログへは**入力・出力の本文を残しません**（`cf-aig-collect-log-payload: false`）。件数・料金・モデル・状態などの記録は残るため、ダッシュボードで利用状況を確認できます。本文も残したいときだけ `AI_LOG_PAYLOAD` を `true` にします。なお、Unified Billing のリクエストは、ログを止めても料金の記録（本文を含まない）が必ず残ります。
- **キャッシュ**：同じ依頼でもAI Gateway のキャッシュは使いません（`skipCache: true`）。APIの応答も `Cache-Control: no-store` にしています。
- **データの送信先**：AI Gateway を通しても、処理は Cloudflare の中だけで終わるとは限りません。Auto Router が外部の提供元（Google・Anthropic・OpenAI・xAI など）のモデルを選んだときは、文章や画像がその提供元へ送られ、提供元のデータ保持の決まりが当てはまります。外部へ送りたくないときは、`AI_AUTO_ALLOWED_PROVIDERS` を `workers-ai` にする、または Workers AI のモデルだけを入れた Model Alias を使ってください。Unified Billing では、提供元にデータを残さない **Zero Data Retention（ZDR）** の経路を使えるモデルがあります（モデルカタログで確認できます）。
- **秘密の値**：パスワードのハッシュ（`APP_PASSWORD_HASH`）と署名の鍵（`SESSION_SECRET`）は Workers Secrets に保存します。AIのAPIキーやトークンはそもそも使わず、フロントエンドにも出しません。
- **パスワード認証**：AIの機能（高精度OCR・要約・翻訳・AI音声）だけにパスワードを設定します（下の「パスワード認証」を参照）。

### パスワード認証（AIの機能のみ）

料金が発生するAIの機能だけに、共通のパスワードを設定します。**ブラウザの音声での読み上げと「通常OCR（無料）」は、これまでどおり誰でも認証なしで使えます。**

- AIの機能を最初に使うとき、小さなパスワード入力を表示します。
- 正しいパスワードを入力すると、サーバー側（`/api/login`）で確認し、**HttpOnly Cookie**（`Secure` / `SameSite=Strict` / 有効期限24時間）を発行します。認証したあとは、そのまま元の処理を自動でやり直します。
- パスワードはサーバー側だけで確認します。Cookieの中身は `有効期限.署名` の形で、書き換えると署名が合わなくなります。
- **パスワードを3回続けて間違えると、しばらく受け付けません。** 最初は約30分で、そのあとも間違えるほど待ち時間が長くなります（最長で約3時間）。`/api/login` は10分あたり10回までに制限しています。
- この回数の記録は Worker の実行環境の中だけに持つため、Cloudflare の別の拠点で処理されたときは数え直しになることがあります。より強く守りたいときは、下の Cloudflare Access の併用をおすすめします。

**Cloudflare Access との併用（任意）**

アプリ全体を Cloudflare Access（Zero Trust）で守っている場合は、`wrangler.jsonc` の `ACCESS_TEAM_DOMAIN`（例: `myteam.cloudflareaccess.com`）と `ACCESS_AUD`（Access アプリケーションの「Application Audience (AUD) Tag」）を設定すると、Access で本人確認できた人はパスワードなしでAIの機能を使えます。Worker は `Cf-Access-Jwt-Assertion` の署名・発行元・AUD・有効期限を確かめます。設定しないとき、または確認できないときは、これまでどおりパスワードで認証します。

**パスワードのハッシュを作る**

```bash
node -e "console.log(require('crypto').createHash('sha256').update('ここにパスワード').digest('hex'))"
```

`SESSION_SECRET` は次のコマンドで作れます（値を変えると、それまでの認証はすべて無効になります）。

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### うまくいかないときの調べ方

AIの機能が失敗したときは、画面の案内のうしろに `（AI-LIMIT）` のような短い印が付きます。秘密の情報は含まれていません。AI音声では、`AI-` のかわりに `TTS-` で始まります。

| 印 | 意味 | 主な対処 |
| --- | --- | --- |
| `AI-401` | パスワードの認証が切れている | パスワードを入力し直す |
| `AI-NOAUTH` | `APP_PASSWORD_HASH` が設定されていない | Workers Secrets に登録する |
| `AI-NOBINDING` | AI Binding（`AI`）が設定されていない | `wrangler.jsonc` の `ai` を確認して再デプロイする |
| `AI-LONG` | 文章が長すぎる（要約は10万文字、翻訳は2万文字まで） | 短く分けて試す |
| `AUTH-401` / `AUTH-LOCKED` / `AUTH-429` | パスワードが違う／続けて間違えた／試行が多すぎる | 入力を確認する／表示された時間だけ待つ |
| `AI-LIMIT` | AI Gateway の利用上限（Spend Limits など）に達した | 時間をおく、または管理者が上限を見直す |
| `AI-BUSY` | Unified Billing の回数制限（2018）で混み合っている | 少し待ってから試す |
| `AI-CREDIT` | クレジットの残高が足りない（402） | 管理者がクレジットを追加する |
| `AI-CONFIG` | AI Gateway の認証・Unified Billing などの設定の問題（401・403） | 下の「Cloudflareの設定」を確認する |
| `AI-G400` | AIが依頼を受け付けなかった（7003 など） | 短い文章・別の画像で試す。モデル名や `AI_AUTO_ALLOWED_MODELS` の値を確認する |
| `AI-G500` / `AI-G503` | AIの提供元・Unified Billing が一時的に使えない | 少し待ってから試す |
| `AI-EMPTY` | AIが文章を返さなかった（1回だけ自動でやり直した後） | もう一度試すか、別の画像・文章で試す |
| `AI-TIMEOUT` | 時間内に終わらなかった | 小さい画像・短い文章で試す |
| `AI-429` | このアプリへの呼び出しが多すぎる | しばらく待つ |
| `AI-HTTP404` | サーバー処理が見つからない | デプロイが終わっているか確認する |
| `AI-NET-B` | ブラウザから通信できなかった | ネットワークを確認する |

詳しい原因は、ダッシュボードの **Workers & Pages → yomiage → ログ**（Worker のログ。状態コードとエラー番号だけを残します）と、**AI → AI Gateway → yomiage → ログ** で確認できます。

初期設定は「Microsoft 七海」（利用可能な場合）と2.0倍速です。七海が利用できない環境では、既定の日本語音声などが自動的に選択されます。

## 公開方法（Cloudflare Workers）

画面（`public/`）は Workers Static Assets として、APIは Worker（`worker/`）として、1つの Worker `yomiage` にまとめて公開します。ビルド作業は不要です。

### Cloudflareの設定（最初に1回）

1. **AI Gateway を作る**：ダッシュボードの **AI → AI Gateway → ゲートウェイを作成** で、名前を `yomiage` にします（別の名前にするときは `wrangler.jsonc` の `AI_GATEWAY_ID` も合わせます）。
2. **認証（Authenticated Gateway）を有効にする**：作ったゲートウェイの **設定（Settings）** で認証を有効にします（Unified Billing の利用に必要です。Worker の AI Binding からの呼び出しは自動で認証されるため、トークンをアプリへ設定する必要はありません）。
3. **ログの本文を残さない**：同じ **設定** で、ログ（Logs）を必要に応じて無効にします。アプリからは本文を残さない指定（`cf-aig-collect-log-payload: false`）を送っているので、有効のままでも件数・料金・モデルだけが記録されます。
4. **キャッシュを無効のままにする**：**設定** の「Cache Responses」は無効（既定）のままにします。
5. **Spend Limits（利用上限）を設定する**：**設定 → Spend limits → ルールを追加** で、上限額（例：月10ドル）と期間を決めます。上限に達したら「Block requests」（既定）にしておくと、それ以上の料金はかかりません。上限は後からいつでも変更できます。
6. **Unified Billing のクレジット**：外部の提供元のモデル（AI音声の `google/gemini-3.8-flash-lite-tts`、Auto Router が選ぶ Google・Anthropic・OpenAI などのモデル）を使うには、**AI → AI Gateway → Credits Available → Manage → Top-up credits** でクレジットを入れておく必要があります。**購入と自動チャージ（auto top-up）の有効化は、管理者の判断で行ってください**（アプリからは行いません）。
7. （任意）**Model Alias**：Auto Router の候補を自分で決めたいときは、**ゲートウェイ → Routing → Create alias** で、例えば `yomiage-text` という名前（`custom/yomiage-text`）を作り、モデルを選んで「Smart routing」にします。`AI_TEXT_MODEL_AUTO` を `custom/yomiage-text` に変えれば、その中から自動で選びます。

| `AI_TEXT_MODEL_FIXED` | 変数 | `google/gemini-3.8-flash` | 固定モデルのときのモデル |
| `AI_TTS_MODEL` | 変数 | `google/gemini-3.8-flash-lite-tts` | AI音声のモデル |
| `AI_AUTO_ALLOWED_MODELS` / `AI_AUTO_ALLOWED_PROVIDERS` | 変数 | 空 | Auto Router の候補を絞る |
| `AI_LOG_PAYLOAD` | 変数 | `false` | AI Gateway のログへ本文を残すか |
| `ACCESS_TEAM_DOMAIN` / `ACCESS_AUD` | 変数 | 空 | Cloudflare Access と併用するとき |

**以前（Vercel・Gemini API）から不要になったもの**：環境変数 `GEMINI_API_KEY`・`GEMINI_MODEL`・`GEMINI_TTS_MODEL`・`GEMINI_HYDROGEN_MODEL`、`vercel.json`、`api/` フォルダー。Google AI Studio の APIキーは、ほかで使っていなければ無効にできます。

`APP_PASSWORD_HASH` が未設定のあいだは、AIの機能だけが「AIの機能を利用できません。パスワードの設定を確認してください。」と表示されます。読み上げと通常OCRはそのまま使えます。

## 対応環境と注意事項

- Web Speech API の `SpeechSynthesis` に対応した最新の Chrome、Edge、Safari などを推奨します。
- 利用できる音声はOSとブラウザによって異なります。日本語音声がインストールされていない環境では、日本語以外の音声だけが表示される場合があります。
- 「オンライン」と表示される音声は、OSやブラウザの仕様によりインターネット接続を必要とする場合があります。このアプリ自体は外部APIへ接続しません。
- ブラウザや端末によって読み上げ方、発音、利用できる速度には差があります。
- ページ送りは読み上げの区切り（ポップアップのドット1つ分）ごとの移動です。文や語の途中からは始められません。
- ほかのアプリが音声を使っている間などは、読み上げの開始が遅れたり、始まらないまま止まったりすることがあります。自動的に検知して読み上げ直しますが、その際は「音声がすぐに始まらないため、読み上げをやり直します」と案内が出ます。
- 一部のブラウザでは、1回の発話が15秒ほどを超えると読み上げが無言のまま止まることがあります。定期的な再開処理と停止検知で自動的に復帰しますが、復帰の際に短い間が空いたり、直前の語句が読み直されたりする場合があります。
- 読み上げエンジンによっては `&` `<` `>` を含む文章で合成に失敗するため、これらは全角の `＆` `＜` `＞` に置き換えて読み上げます。
- 社名などの英語の略語（`Pte.` `Ltd.` `Co.` `Inc.` `Corp.` など）は、略したままだと不自然な読み方になるため、`Private` `Limited` `Company` のように省略しない単語に置き換えて読み上げます。
- `VW` は別の言葉（フォルクスワーゲンなど）に誤読されるため、「ビークルウォッシャー」（Vehicle Washer：車両を洗う洗車機）と読み上げます。英語のつづりのままだと「Washer」が部品の「ワッシャー」のように読まれるため、読み方をカタカナで指定しています。`VWX` や `VW2` のように英数字が続く場合と、小文字の `vw` は置き換えません。
- `TW-STK`（Tower Stocker）は「タワーストッカー」と読み上げます。
- `T-BOX`（`T-Box`）は「ティーチングボックス」と読み上げます。
- `STK` は「ストッカー」と読み上げます（`TW-STK` は「タワーストッカー」のままです）。
- フルネームは読み間違えが多いため、「名字＋さん」に置き換えて読み上げます。登録した氏名は、`中西 健太朗`・`中西健太朗`（姓と名のあいだの空白はあってもなくても可）を「なかにしさん」、`村田 三平` を「むらたさん」、`衣 朗`・`衣 朗（Yi, L.）` を「イーさん」、`林 漢昇`・`林漢昇 <hansheng_lin@muratec.com.tw>` を「リンさん」、`楳生 仁子` を「うめぶさん」、`谷内 好和` を「やちさん」、`孫 豊堯` を「ソンさん」、`黒木 慶人` を「くろきさん」、`Outen, Lee`・`Lee Outen`・`Outen, Lee <lee.outen@muratec-usa.com>` を「リーさん」（英語の氏名は `LATIN_FULL_NAME_READINGS` に「名字, 名: 呼ぶときの読み方」で登録します。`Outenさん` のように名字に敬称が続くときも「リーさん」）と読みます（氏名のすぐ後ろのローマ字の表記やメールアドレスは読みません）。登録していない氏名でも、`張 偉（Zhang, W.）` のように後ろに「名字, 名」の形のローマ字の表記が付くときは、ローマ字を手がかりに日本語での読み方（カタカナ）にして「チャンさん」と読みます（英語読みにはしません）。中国・韓国のよくある名字は `script.js` の `ROMANIZED_SURNAME_READINGS` にカタカナの読みを登録しており、それ以外はローマ字をそのままカタカナに直します（`Tanaka` → タナカ）。氏名のすぐ後ろにメールアドレスが付くとき（`陳大文 <tawen.chen@example.com.tw>`）も、`@` より前に `ROMANIZED_SURNAME_READINGS` の名字があれば、それを手がかりに「チェンさん」と読みます（メールアドレスは読みません。名字が見つからないときは元の文章のまま読みます）。`様` や `氏` などの敬称が続くときはその敬称を使います（`村田三平様` は「むらた様」）。登録していない氏名でも、`山田 太郎さん` のように姓と名のあいだに空白があり敬称が続くときは「山田さん」と名を省いて読みます（`営業部 部長様` のような部署名・役職は対象外です）。氏名を追加するときは、`script.js` の `FULL_NAME_SURNAMES` に「姓 名（空白1つ）: 名字の読み方」を追加します。
- 名だけで書かれたときの読み方は `WORD_READINGS` に登録します。`健太朗` は「けんたろう」、`三平` は「さんぺい」と読みます。
- 住所に含まれるアメリカの州の略称（`Charlotte, NC 28273` の `NC` や `NC州` など）は、1文字ずつ読まれて州名だと伝わらないため、`North Carolina` のように省略しない州名に置き換えて読み上げます。`OK` `OR` `IN` のように英単語と同じつづりの略称は、郵便番号が続くときか「州」が付くときだけ置き換えます。
- `MURATA MACHINERY USA, Inc. CLT` の `CLT` のような、アメリカの拠点を表す3文字の都市コード（空港コード）は、`Charlotte` のように都市名に置き換えて読み上げます。ほかの意味の略語（建材のCLTなど）と取り違えないよう、文章中に `USA` `米国` `アメリカ` などアメリカを示す言葉があるときだけ置き換えます。
- 画像の文字認識（OCR）はCDNからTesseract.jsと日本語の学習データを取得します。社内ネットワークなどでCDNへ接続できない環境では利用できません。
- 「AIで高精度OCR」「AIで翻訳・要約」「AI音声」は、Cloudflare Workers へのデプロイ（または `wrangler dev`）と AI Gateway の設定が必要です。`public/index.html` を直接開いた場合は利用できません。
- AI音声は料金がかかります。**「✨ AI音声で読み上げ」をONにしたときだけ**使い、ページを開き直すとOFF（無料のブラウザの音声）に戻ります。
- スマートフォンでは、画面を一度も触っていない状態で音を鳴らせないブラウザがあります。最初の操作で無音を鳴らして解除していますが、それでも鳴らないときは、画面をタップしてからもう一度読み上げてください。
- OCRの処理時間は画像の大きさと端末の性能によって変わります。大きな画像ほど時間がかかります。
- クリップボードの自動読み取りはブラウザのセキュリティ制限を受けます。許可ダイアログをWebアプリ側から省略することはできません。Cloudflare WorkersなどのHTTPS環境、またはlocalhostでの利用を推奨します。`index.html`を直接開いて毎回確認される場合は、入力欄への `Ctrl + V` を利用してください。
